# Neo Earth Radio — project guide for Claude

**NEO // EARTH** (Neo Earth Radio, neoearthradio.com, formerly Signal Wave): random live music radio from a random city on Neo-Earth, played over a neon cyberpunk globe. Built for Matt, who mostly uses it as a home-screen app on his iPhone. Live site deploys from `main` on Vercel. README.md is the human setup guide; this file is the working map for making changes.

## Purpose (judge every change against this)

**New music discovery, in the exact genre you love, from artists around the world.** Pick a genre (down to a style like Classic Rock) and hear that genre, not whatever a station happens to tag itself with, and discover new artists from the country the station is in: a Tokyo classic rock station should ideally be playing Japanese classic rock bands (Matt, 2026-11-13). Exact genre comes first; local artists are preferred, but stations that mix local and famous international artists are not skipped. "New" means new to the listener, not newly released: overlooked older local artists count just as much (Matt: "just anything that slaps"), so there's no filter on release date or popularity outside era styles like Classic Rock. So: real local stations in real cities, spread across the world; not curated internet-only channels or playlists of familiar songs (Matt ruled out adding Nightride FM / SomaFM / laut.fm-style networks for this reason). **Random play never repeats a station** a listener has heard before; saving a station is how you come back to it. Quality guardrails stay strict: streams must start fast, send real artist/song titles, and meet a minimum bitrate.

## Ground rules

- **Pushing to `main` deploys the live site.** Matt has asked for changes to go straight to `main` once tested; for anything risky or large, push a branch first (Vercel builds a preview) and ask.
- **Test before pushing:** `npm test` (offline tests) and a Playwright check at iPhone width (390×844). `node server.js` serves the site and `/api/*` locally (`PORT=3123 node server.js`). The sandbox usually can't reach Radio Browser, so real stations won't load locally; the Easter egg (below) is a handy way to get audio playing for UI tests.
- **After any change in `public/`, bump the cache name in `public/sw.js`** (`signal-wave-vNN` → next number) so installed copies update, **and bump `BUILD` near the top of `public/app.js`** (shown as "BUILD NN" at the bottom of the Saved panel; Matt uses it to check his phone has the update). If you add a new front-end file, add it to `SHELL` in `sw.js` too.
- Phone first: everything must work at 390px wide, with safe-area insets, and on iPhone Safari (no Web Audio analyser on streams, no element full screen). Respect `prefers-reduced-motion`.
- Keep it light (Matt's friend saw high CPU in Safari, build 51): no `mix-blend-mode` or `backdrop-filter` over the globe (the compositor redoes them every frame as it moves; WindowServer on Macs), no per-item meshes on the globe (merge them), and no globe.gl hover/click handlers (they turn its per-frame ray-casting back on).
- No build step and no npm dependencies: plain HTML/CSS/JS. Vendor libraries are bundled in `public/vendor/` (no CDNs).
- Visual style: black background, neon yellow `#fcee0a`, cyan `#00f0ff`, magenta `#ff2a6d` / pink `#ff3ec8`, green `#39ff14`; Chakra Petch display font, Share Tech Mono for HUD text; terminal-style status messages like `> LINK ESTABLISHED`. CSS tokens live at the top of `styles.css`.
- Write commit messages in plain language describing what changed for the user.
- **Plan, then delegate (Matt, 2026-11-14):** the main session plans (Opus, high effort) and hands code changes to the `neoearth-coder` agent (`.claude/agents/neoearth-coder.md`: Sonnet, high effort) with a written spec; it edits and tests but never commits. The main session reviews the diff and screenshots, then ships. Tiny one-line fixes can skip the hand-off.
- **In-world text follows the lore.** Before writing or changing splash copy, status messages, vibe-mode alien lines (`UFO_LINES` in `vibes.js`), toasts or Easter eggs, read [docs/LORE.md](docs/LORE.md) (Matt's Neo-Earth lore; he writes it, Claude doesn't add canon). Keep its "Where lore shows up" list current when in-world text changes.

## How it works

### Server (Vercel functions in `api/`, shared code in `lib/`)

| Endpoint | Purpose |
|---|---|
| `api/next.js` | One vetted station: first from the **station shelf** (`lib/pool.js` `poolNext`: `pool_candidates` RPC by genre keys, minus heard/reported, regions not recently heard, local-artist weighting, then up to 9 candidates probed in parallel batches of 3 (2.5 s to first audio; with a genre picked the probe also reads the current song title, 4 s, and **the song playing right now must fit the pick**: `songFits(title, spec)` is false only for a clear mismatch, which skips that station without marking it offline; unknown (no "Artist - Song" title, not in Apple's catalog, slow lookup) passes; Any and World are never judged; lookups share the persistent `song_lookups` cache via `lib/songcache.js`); a station offline gets `pool_mark_fail`; the first passing one in weighted order wins), else the live vetting below. The app POSTs `{ genres, exclude, recent }` (exclude = every station heard on this device, up to 6000); GET `?genres=…&exclude=…&recent=…` still works. Up to 5 genres; `recent` country codes steer picks to other parts of the world |
| `api/nowplaying.js` | Current song title by station UUID (reads ICY metadata): `{ ok, title }`. With `&genres=<ids>` (same format as `/api/next`) it also returns `fits` true / false (a clear mismatch) / null (can't tell), judged by `songFits` with the `song_lookups` cache, on tighter timeouts (2.5 s); the app asks this before tuning an old queued station (see Station fetching). `{ ok: false, unknown: true }` means the station couldn't be looked up (directory down), not that its stream is dead. Whenever it reads a title that differs from the newest stored for the station it adds a row to `station_songs` (`lib/songlog.js`: in-memory last-title map per warm instance, fire-and-forget after the response, silent if the table is missing); the Apple apps use this endpoint, so its default response stays `{ ok, title }` |
| `api/station.js` | Looks up one station for a shared link (doesn't require song titles) |
| `api/track.js` | Logs a play after 30 s of listening (server key; random per-browser visitor ID) |
| `api/admin-stats.js` | Dashboard numbers, only for `ADMIN_EMAILS`; also `POST { action: 'review', ids, status }` to AGREE (`approved`), DISMISS (`rejected`) or undo (`pending`) wrong-genre reports, and `POST { action: 'history', uuid, genres }`: a reported station's last songs (up to 10, newest first, merged and de-duplicated by title, each labelled **SERVER** (the station's own recently-played page, `lib/stationhistory.js`: SHOUTcast `/played?sid=1&type=json` / `played.html`, AzuraCast `/api/nowplaying/<shortcode>` for `/listen/<shortcode>/…` streams, Centova `/recentfeed/<user>/json` and `/external/rpc.php?m=recenttracks.get` for `/proxy/<user>/…` streams; https only, 3 s timeouts, private addresses refused and the checked address pinned so the admin can't be used for SSRF; the formats were written from the vendors' documented shapes and have not been checked against live servers), **LISTENERS** (`station_songs`), **SCOUT** (the shelf's last 10 samples) or **REPORT** (songs attached to reports)), with Apple's genre and a ✓ / ✗ / ? against the reported genres (`song_lookups` cache first, at most 10 new iTunes lookups per request) |
| `api/nese.js` | NESE member ID and transmissions: `GET` (ID + inbox, assigns an ID on first call; admins get 0), `POST {action:'send', to, station}`, `POST {action:'dismiss', id}`. Signed-in users only; server key; calls the `nese_*` SQL functions. `lib/nese.js` formats/parses IDs |
| `api/feedback.js` | `POST { visitor, genres, song, station }` from the WRONG GENRE? button: one `genre_reports` row per picked genre, always status `pending` (the admin's own included: nothing is approved except by AGREE in /admin). In the app a tap is only a strike for that listener (see the WRONG GENRE? bullet); the report is what reaches /admin. `lib/reports.js` loads approved reports (cached 5 min) and `nextStation` excludes those stations for that genre (with several genres picked, only if reported for all of them). When a listener's report takes the reports waiting for review from 3 or fewer to more than 3, `lib/notify.js` emails the admin once via Resend (list + link to /admin); it fires again only after reviews bring the count back down |
| `api/genre-counts.js` | `?genre=metal` → candidate station counts for the genre and each style (secure stream + a placeable city: coordinates or `cityFromText`, aliases included, capped at 300 per name, cached a day). Uses `STYLES` from `lib/config.js`, which must match `CATALOG` in `app.js` (a test checks this) |
| `api/config.js` | Tells the browser whether sync is configured (public URL + anon key only) |
| `api/keepalive.js` | Daily cron (`vercel.json`) so free Supabase doesn't pause |

Station vetting (`lib/vet.js`), the five checks: directory filters → music-only tags (talk/news/sports blocklist) → has a city (offline reverse geocode, `lib/geo.js` + `cities.json`; stations without coordinates are placed by `placeFromStation`/`placeFromFields` (`lib/geo.js`), first match wins: their directory region field (tolerant of admin words like Prefecture/Province and "City, Region"), a 100k+ city in the name, a whole tag naming a 50k+ city, then a 100k+ city in the homepage or stream address (generic words like radio/stream/fm peeled off; joined names like saopaulo). Always the station's own country; `lib/city-aliases.js` adds ~400 exonyms and native spellings (Munich/München, 東京, Saigon); `NOT_PLACES` and genre words never place; first-level region names in US/CA/AU/BR/MX/IN (`REGION_NAMES`: "Indiana", "New York", "São Paulo" as a region) place nothing, since they don't say which city; **when no city is found but the country is known, the station still plays at country level** (Matt, 2026-11-18): `city: null`, `region` = the cleaned state field (`cleanRegion`), position from `countryCenter(cc)` (population-weighted, dateline-safe) or the station's own coordinates when near its country's cities; the app shows **CITY DATA CORRUPTED** with a CSS static effect (`.city-glitch`, no animation under reduced motion) and COUNTRY as "Indiana, United States"; shelf picks weight these ×0.6; searches no longer ask the directory for coordinates only, and fetch 100 per country / 200 worldwide) → stream starts fast → sends real song titles (`lib/icy.js`; Shift-JIS titles are decoded when they come out as real Japanese; `looksLikeSong` also accepts ／ ｜ －, 「」『』 and " / " in CJK text) → meets the quality floor (`LIMITS.minKbps` 64, AAC `minKbpsAac` 40, when the bitrate is known; failures logged as `low_quality`). **Genre focus** (`isFocused` in `lib/vet.js`): for a chosen genre, at most one other-genre tag may come before it in the station's own tag order (decades and words like "music" don't count; same-family styles like hard rock before classic rock are fine), or the genre is in the station's name; stations spread across 4+ main genres are variety stations and skipped. Not logged as a failure (genre-specific). **Song check** (`lib/songcheck.js`): the song playing during vetting is looked up in Apple's iTunes Search API (free, no key, 2.5 s timeout, cached); its genre must fit the pick (`FITS` per main genre, styles via their parent in `STYLES`), and era styles (`ERAS`: classic rock ≤ 1994, 80s/90s/00s, motown…) use the earliest release year so remasters don't count. Unknown songs, failed lookups and World pass; a clear mismatch skips that station for that genre for 3 hours (`offGenre`). **Local artists** (`lib/artistcheck.js`): the current song's artist is looked up in MusicBrainz (country of origin; ~1 request/s, spaced and cached, at most 3 per search, User-Agent from `USER_AGENT`); each station keeps a local/foreign record and `pickLocal` weights picks from 1 (all foreign) to 4 (all local), 1.5 when unknown. Never rejects. Stations carry `localArtist` (true/false/null). Styles also search and match their other names (`TAG_ALIASES` in `lib/config.js`, e.g. synthwave → retrowave/outrun/darksynth, drum and bass → dnb); keep aliases specific since matching is by substring. **Translation layer** (`lib/translate.js`): `translateTags` adds English words for foreign tags (ロック → rock, música electrónica → electronic, ニュース → news), so genre matching, the music check and the talk/news/sport/religion blocklist work in other languages; it's an offline word list: `DICT` there (music/news/talk words and a few genres) plus **`lib/genre-words.js`**, every main genre and style in ~30 languages by language code (≈800 words). When several words match one tag the longest wins (クラシックロック = classic rock, not classical); short words are padded with spaces to match whole tags only (' ダブ '). `COUNTRY_LANG` maps each searched country to its language, and region searches add one search per country in that language (`nativeWords`: サイケ in Japan, psicodéli in Brazil). Region searches also pull 100 of each country's stations with no keyword, so locally tagged stations are found. Region searches always use the style's own name plus one alias; the worldwide fallback searches all names (up to 8) in parallel. Passing stations are pooled per genre in memory (resets on cold start); failures are remembered for a while; results are logged to Supabase `station_checks` (`lib/checklog.js`). `lib/radio.js` is the Radio Browser client with mirror failover. **Tune genres, tags, blocklist and timeouts in `lib/config.js`.** `probeStream` also records whether a stream sends CORS headers (`cors`), which decides if the browser can analyse its audio.

**Station shelf** (migration `20261118040000_station_pool.sql`: `station_pool`, `song_lookups`, `scout_runs`, RPCs `pool_candidates`, `pool_stats`, `pool_mark_fail`): filled by `scripts/scout.js`, run every 30 min by `.github/workflows/scout.yml` (GitHub Actions; repo secrets `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`; scheduled runs only work from `main`, and GitHub pauses them after 60 days without repo activity). The scout discovers from Radio Browser's **whole list of working stations** (`allStations()`, downloaded at most daily and kept in the GitHub Actions cache as `.scout-cache/rb-stations.json.gz`; `lib/scoutlist.js`: cheap offline checks first, then countries with the fewest shelf stations go first, round-robin, max 40 per country per run), plus ~20 top-up searches for recently changed stations (falling back to the old rotating keyword searches if the list is unavailable), and the Icecast directory (`dir.xiph.org/yp.xml`, empty as of 2026-11-17, then the old experimental `api.dir.xiph.org/experimental/full`; first endpoint with entries wins, never the HTML pages; https streams only, placed only by an unambiguous 300k+ city name via `cityAnywhere`; ids are deterministic UUID-format hashes of the stream URL, version nibble 5), runs the same hard checks patiently, and re-checks stations, keeping the last 10 song samples. Genres are judged across samples (`qualifyGenres` in `lib/shelf.js`): a key qualifies when ≥3 known songs and ≥60% fit (main genres and era styles only), or when the station's tags match and pass `isFocused` and known songs don't contradict it (≥50%); other styles need the tags. iTunes lookups are cached in `song_lookups` and capped (~15/min, 250/run). 3 failed checks → dead (retried weekly). `/api/station` and `/api/nowplaying` look up shelf stations too (Icecast ids aren't in Radio Browser). Admin shows a STATION SHELF panel.

Env vars (Vercel): `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (server only, never sent to browsers), `ADMIN_EMAILS`, optional `SITE_URL`, optional `RESEND_API_KEY` (+ `NOTIFY_EMAIL`, `NOTIFY_FROM`) for the review-alert email (`lib/notify.js`). `lib/supabase-env.js` tolerates name typos. `scripts/build-meta.js` (`npm run build`) makes link-preview URLs absolute at deploy.

## Features (current)

- Random vetted music station worldwide, globe flies to its city with an arc from the last one; NEXT/PREV, two stations always queued.
- **Resume:** JACK IN continues the last station played (this device, or the newest across devices when signed in); the splash says `> LAST SIGNAL: <NAME> // JACK IN TO RESUME` and the status line `> RESUMING LAST SIGNAL…`. Shared links and first-visit onboarding come first; forgotten stations aren't resumed; a dead stream falls through to a random station via `troubled()`.
- Now playing with song titles, station/genre/city/country, bitrate, visualizer, Spotify and Apple Music search links, lock-screen controls.
- **Track log** (LAST 5 tab on the panel's right edge, Esc closes): the last 5 songs heard on this device, newest first (`sw.songLog`, logged in `setSong` via `logSong`; the Easter egg isn't logged), each with song, artist, time ago, flag/city/station and SPOTIFY / APPLE MUSIC buttons that open a search in each app. Always exactly the panel's height (Matt's call): compact rows fit all five, and the list scrolls if the panel is ever shorter. On a phone it slides over the panel; on desktop it pops out beside it. One-tap adding: Apple Music is possible later with MusicKit (Matt's developer account); Spotify isn't, since its API now limits unapproved apps to 5 allow-listed users (approval needs 250k monthly users and a registered business).
- **First visit:** after JACK IN, new listeners (no saved genre list) get "WHAT DO YOU WANT TO HEAR FIRST?": pick a genre, then a style or ALL <genre>, or SURPRISE ME (defaults, Any). Their list starts as the pick + related genres, 5 in all (`RELATED` in `app.js`), with the pick selected. Shared links skip it.
- A small fixed EDIT button sits at the end of the genre row (always visible; the chips scroll). The editor explains: add as many genres as you like, pick up to 5 at a time to rotate through. Opening a genre in the editor loads station counts next to each style (`loadGenreCounts`, an upper bound; empty styles are dimmed). Adding a genre while nothing is selected (Any) selects it.
- Genre chips, mix up to 5; editable list with sub-genres; dead genres flagged. 15 main genres: Electronic, Rock, Metal, Punk, Pop, Hip-hop, R&B & Soul, Jazz, Blues, Classical, Ambient & Chill, Latin, Reggae & Ska, World, Country & Folk, each with roughly 4–17 styles (`CATALOG` in `app.js`; main-genre ids and search tags must match `GENRES` in `lib/config.js`). Tags match by substring, so avoid short tags that hide inside other words (e.g. "oi", or "dub" as a main tag).
- Saved stations (♥), shown on the globe; a pink note at the top of the saved list (and the save toast, `> SIGNAL SAVED // FIND IT UNDER NESE` or `SAVED`) explains that only stations saved with ♥ on the player appear there (the note has a ✕ to dismiss it for good on that device); share by link; **FORGET SIGNAL** (under the status line) skips a station and never plays it on this device again (`sw.hidden`, synced when signed in). It replaced "Not music? Hide station" in build 42, since ad breaks made that wording misleading. EXPORT / IMPORT sit right under the saved list (above "Add received signal"); EXPORT turns the list into a checklist (tap rows, SELECT ALL / NONE, EXPORT N, CANCEL) and downloads only the picked stations in the usual file format.
- **NESE membership** (signed-in users): each gets a NESE ID (Matt, as admin, is NESE-0000; others count up from NESE-0001). The Saved button reads NESE, the panel becomes the NESE DASHBOARD with an ID badge, with two tabs: SIGNALS (saved list) and TRANSMISSIONS (pick the playing signal or a saved one, enter a member's NESE ID, TRANSMIT or COPY LINK INSTEAD; a saved row's link button opens this tab with that signal picked). Received stations wait under INCOMING TRANSMISSION SIGNALS on the TRANSMISSIONS tab (green dot on the button and the tab, toast on arrival) until ADD (saves it via `/api/station`) or ✕; the same station sent more than once shows as one row listing every sender, and ADD/✕ clears every copy. Added or dismissed ones are kept off screen (`sw.neseGone`) until a refresh from the server no longer has them, and the delete is re-sent if it hadn't gone through. Only IDs are ever shown, never emails.
- **WRONG GENRE?** (small button under the status line, only when genres are picked): skips to the next station (`> WRONG GENRE REPORTED — RETUNING…`) and reports it via `/api/feedback`, but one tap doesn't condemn a station (many mix genres): it adds one **strike** per picked genre for that station, for this listener (`sw.genreStrikes`). At **10 strikes** for a (station, genre key) the station is **blocked for that genre for this listener only** (`sw.genreBlocks`, synced to `user_settings.genre_blocks` and unioned across devices; status/toast `> SIGNAL BLOCKED FOR <GENRE>`): `fetchStation` puts blocked stations in `exclude` in every mode, repeats included, when they are blocked for **every** selected genre key (the rule the server uses for agreed reports), so a station blocked on Metal can still come up on Pop; `takeQueued` also skips them. Matt reviews reports in `/admin` (WRONG GENRE REPORTS panel: station links open it in the app to listen, **SONGS** opens the station's last 10 songs with source labels, Apple genre, ✓ / ✗ / ? and SPOTIFY / APPLE MUSIC links, to tell a pattern from a picky listener; AGREE / DISMISS / undo); agreed reports stop that station being picked for that genre for everyone. Everyone's reports start `pending`, the admin's too. **COPY AGREED REPORTS FOR CLAUDE** copies them as text: when Matt pastes those, look for the pattern (which tag or alias let the station in, whether the song check should have caught the song, a missing translation or an over-broad `FITS`/alias) and tune `TAG_ALIASES`, `lib/genre-words.js`, `isFocused`, `FITS`/`ERAS` so similar stations are caught too.
- Optional sign-in and sync across devices; private admin dashboard with plays, listeners, top stations/countries/genres, station-check stats, wrong-genre reports to review.
- Installable PWA with icons and link-preview image.
- **Vibe mode** (button under the reticle, or `V`): hides the HUD; globe zooms out to fill the screen with a tiny ◂ ▸ bar. `vibes.js` draws warp stars, ship squadrons that fire on the beat and aim at asteroids, asteroids that explode (big ones split), soft beat rings once a bar, and the Kryx UFO (Neo-Earth's secret protectors, per the lore) that lowers a disco ball throwing light spots; the orbs occasionally fire at asteroids on the beat. Its lines (`UFO_LINES`) are radio chatter like "> GALACTIC REQUEST LINE OPEN, NEXT TRACK: PROTECT NEO//EARTH" and wrap to fit the screen; nothing abduction-themed. Matt asked for it calm, not busy: keep spawn rates low. Real beat sync only on streams with CORS on desktop (bass-flux detection; when no clear hit is heard for a beat's length the genre tempo fills in, so steady music still drives the effects); iPhone uses a genre-tempo fake beat. **Tap or click an asteroid** to fire a yellow shot from the playing signal's city (`globe.getScreenCoords`), 75% hit chance; misses are aimed just wide (`PLAYER_HIT_CHANCE`, `fireAt` in `vibes.js`). Bolt hits use swept checks so fast shots can't skip small rocks. Space still pauses (Matt decided against Space to fire). Full screen via the Fullscreen API (webkit fallback); iPhone Safari can't, the home-screen app fills the screen.
- **Easter egg:** typing `wreckingcrew.mp3` in Saved → "Add received signal" plays `public/media/wreckingcrew.mp3` (55 s Space Jam theme clip, measured 132.1 BPM, first beat at 261 ms) as station WRECKING CREW from Jacksonville. Globe zooms out and dribbles like a basketball; status line is locked to blinking red `> LINK HACKED // STREAM CORRUPTED // JAM IMMINENT` for the whole song; a red TERMINATE REMOTE USER button appears under the status line and returns to normal radio; when the song ends it goes back to radio. Can't be saved; not counted in stats; cuts in even mid-search (`state.eggAt`). **In vibe mode during the egg**, five neon wireframe basketballs (orange outline, yellow seams, turning magenta equator, faint body) orbit close to the globe on tilted orbits at 1.1–1.4× its radius, slowed ~20% in build 46 (`newBall`/`placeBall` in `vibes.js`). Each trails one smooth fire tail traced along its orbit that narrows and fades out (Matt: no separate orbs or sparks), and a faint dashed orbit line shows its path, hidden behind the globe. Orbits ride along with the dribble (`globeOnScreen()` in `app.js` reads the bouncing layer); on tall phone screens the orbits stand upright and the camera pulls back to `eggAltitude()` 4.6 so they fit). Tap one to shoot it (75% hit chance; a hit shot homes onto the ball): it bursts into basketball fireworks (rim and net, sparks, a crackling second burst, a shower of mini basketballs) with an announcer call, a shout plus its sound from `public/media/jam/` (`CALLS` in `vibes.js`, played by `jamCall` through a Web Audio mixer so it layers over the track on iPhone; unlocked and preloaded inside the tap that starts the egg). Shot balls come back after ~4 s; when the track ends they all go off at once (FINAL BUZZER!). The announcer clips are NBA Jam sound bites Matt supplied (trimmed and loudness-matched); swap them for original sounds before any App Store release or monetization.

## Origins and key decisions

The app was planned and first built in a separate claude.ai chat, "Cyberpunk world radio website" (2026-11-07), with a build-plan doc ("Signal Wave — Random World Radio: Build Plan", https://claude.ai/artifact/UnEt9UqrMz2DsF9UdPPSG2). The decisions there still shape the code:

- **The brief:** a mobile-friendly site that plays a random radio station from around the world; dark cyberpunk look (black, neon, inspired by the Cyberpunk game but with original branding); a tech-style globe that rotates and zooms to the station's city; a display with song, genre, station, city and country; and favorites. Matt later sent a reference image and asked for the globe to look more like it, which led to the neon network look (hex-dot countries, glowing arcs and particles).
- **Music only, and strict:** Matt wanted no talk radio and real song titles, so every station must pass five checks (directory filters, music tags with a talk/news/sports blocklist, a city, a stream that starts within 4 s, real ICY song titles). This shrinks the pool a lot, which is why stations are vetted server-side, pooled per genre, and two are kept queued.
- **Region-balanced picks:** picks are spread across world regions, steering away from countries just heard, so it doesn't keep landing in the US and Europe.
- **City lookups are offline** (`lib/cities.json`, ~49,000 places with 5,000+ people). The first version used OpenStreetMap Nominatim, which rate-limits and often blocks Vercel's servers; every station then failed "has a city" and was benched for hours ("no stations passed the checks"). Fix: offline list, city check first, slow stations benched 20 minutes instead of 6 hours, one quiet retry.
- **Never skip a playing station for missing titles.** Early versions skipped on missing or repeated titles and on the browser's false "stalled" event, cutting songs off. Now only a real stop of 8 s counts, a station that was playing gets one reconnect a minute, and missing titles just leave the last song on screen.
- **Globe freezing on iPhone:** caused by hovering/touching the unnamed particles around the globe, which threw an error inside globe.gl and stopped its animation (switching tabs restarted it — Matt's clue). Fixed, plus a watchdog that restarts or rebuilds the globe if it stops drawing (iOS can drop the WebGL context), a lower render resolution on phones, and zoom limits so the camera can't pass into the globe.
- **Sign-in uses an emailed code, not a link,** because a link opens Safari instead of the home-screen app. Sync is optional; without Supabase everything is saved per device.
- **Dashboard privacy:** plays count after 30 s; listeners are a random per-browser ID (no IPs or locations); only `ADMIN_EMAILS` can see `/admin`; the service key never reaches the browser.
- **Updates:** network-first service worker plus a build number shown in the Saved panel, so Matt can confirm his phone has the latest version after closing and reopening the app.
- **Name:** started as the placeholder "Neon Atlas"; Matt was offered ten options (Ghost Frequency, Gridcast, Carrier Wave, Signal Drift, Neon Meridian and others) and chose **Signal Wave** as a working name. "ER" (Earth Radio) was added after finding Signal Wave Radio, then the app became **NEO // EARTH** (Neo Earth Radio) once Matt registered neoearthradio.com.
- Matt originally uploaded files to GitHub by hand; since connecting GitHub, Claude pushes directly.

## Known limits and ideas not done

- Most stations don't send CORS headers, so the browser can't analyse their audio; iPhone never analyses streams (Safari breaks background playback through Web Audio). True sync everywhere would need a streaming relay (e.g. a Cloudflare Worker); Vercel functions time out and add bandwidth cost.
- The live fallback's pool is still in serverless memory; the persistent pool is the station shelf (Supabase).
- HLS streams are skipped (no ICY titles).
- `USER_AGENT` in `lib/config.js` names neoearthradio.com; update it if the domain changes.
